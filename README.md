# subs-translator

Переводит `.srt`-субтитры **реплика за репликой** против OpenAI-совместимого API, но не «в вакууме»:
модель видит синопсис фильма (тон, регистр, глоссарий имён), уже сделанный перевод предыдущих реплик
и оригинал следующих. Поэтому `ты`/`вы` выбираются осмысленно, имена не «плывут» от сцены к сцене,
а ответ читается как ответ.

Один вызов API на реплику (~900–1400 на полнометражный фильм). Строго последовательно, без concurrency.

## Установка

Нужен Node.js ≥ 24 (либо собранный бинарник — см. «Разработка» в конце).

```sh
npm install
cp .env.example .env      # и вписать ключ
```

`.env`:

```
OPENAI_API_KEY=sk-...
SUBS_BASE_URL=https://api.paretoinference.com/v1
SUBS_MODEL=z-ai/glm-5.3-flash
GROQ_API_TOKEN=gsk-...        # STT (Whisper), см. «Аудиодорожка → субтитры»
STT_MODEL=whisper-large-v3-turbo
```

Любое значение можно переопределить флагами `--api-key` / `--base-url` / `--model`;
вместо `SUBS_BASE_URL` подойдёт `OPENAI_BASE_URL`.

## Использование

```sh
subs-translate movie.srt                      # → movie.ru.srt (+ sidecar во временной папке)
subs-translate movie.srt --limit 5            # пробный прогон: первые 5 реплик
subs-translate movie.srt --range 100-130      # только реплики 100–130
subs-translate movie.srt --resume             # докончить после обрыва
subs-translate movie.srt --dry-run            # показать полный промпт первой реплики и выйти
subs-translate movie.srt --about-file notes/synopsis.md
subs-translate movie.srt -o out/ru.srt
subs-translate movie.srt --price-in 0.3 --price-out 1.2   # + оценка стоимости
subs-translate movie.mkv                      # видео: список встроенных дорожек и выход
subs-translate movie.mkv --sub-track 0        # видео: извлечь дорожку 0 и переводить её
subs-translate movie.mp4 --audio-track 0      # видео: речь из аудиодорожки 0 → субтитры → перевод
```

Прогресс (реплика k/n, время, ETA, токены) идёт в stderr; stdout остаётся чистым. `-q` выключает прогресс.

### Интерактивный режим

```sh
subs-translate                  # без аргументов в терминале — вопросы с выбором стрелками
subs-translate movie.mkv -i     # то же, файл уже выбран
```

Утилита спрашивает по шагам: файл (список `.srt` и видео из текущей папки), дорожку видео
(субтитры или речь → Whisper; растровые дорожки не выбираются), синопсис (готовый about-файл,
другой файл или текст, введённый/вставленный прямо в терминал — конец ввода: две пустые строки
подряд или Ctrl+D; введённый текст можно сохранить в `<вход>.txt`, тогда он подхватится и
при `--resume`), куда сохранить перевод, продолжать ли по sidecar (если он есть), что сделать
(весь файл, первые N реплик, диапазон или только промпт) и, если в папке есть `endpoints.json`, —
один endpoint или несколько.
Перед запуском печатается та же команда флагами — её можно скопировать и запускать без вопросов.
Флаги, заданные вместе с `-i`, не спрашиваются; остальные настройки берутся по умолчанию.
Без терминала (stdin/stdout в pipe) интерактивный режим не включается.

### Видео со встроенными субтитрами

Вместо `.srt` можно скормить видеофайл — субтитры вытаскиваются системными `ffprobe`/`ffmpeg`
(должны быть в PATH; бандлить их с утилитой не нужно):

```sh
subs-translate movie.mkv                  # печатает список встроенных дорожек и выходит
subs-translate movie.mkv --sub-track 0    # извлечь дорожку 0 и переводить её
```

- без `--sub-track` печатается таблица дорожек: номер (то, что идёт в `--sub-track`),
  кодек, язык, заголовок; растровые дорожки (PGS, DVD/VobSub, DVB) помечены — их
  в текст не извлечь;
- с `--sub-track N` дорожка конвертируется в SRT и сохраняется во временной папке
  (`movie.track0.eng.srt`, язык берётся из метаданных), дальше весь пайплайн работает
  с этим файлом: выход — `movie.track0.eng.ru.srt` рядом с видео, sidecar и `--resume`
  как обычно (продолжать — тем же `movie.mkv --sub-track N --resume`);
- если рядом с видео лежит `movie.txt` или `movie.md`, он подхватывается и для извлечённого входа;
- повторный запуск перезаписывает извлечённый файл (это дёшево) и продолжает по sidecar.

### Аудиодорожка → субтитры (STT)

Если субтитров в видео нет, речь можно транскрибировать Whisper'ом через
OpenAI-совместимый endpoint (по умолчанию — Groq) и сразу перевести:

```sh
subs-translate movie.mp4                  # печатаются оба списка: субтитры и аудио
subs-translate movie.mp4 --audio-track 0  # речь → субтитры → перевод, одним прогоном
```

- без флага показываются оба списка дорожек; `--audio-track N` и `--sub-track N`
  взаимоисключающие;
- конфигурация STT — три переменных (флаги `--stt-model` / `--stt-base-url` /
  `--stt-api-key` переопределяют): `STT_MODEL` **обязателен** (дефолта нет —
  модели у провайдеров называются по-разному), `STT_API_KEY` (fallback —
  `GROQ_API_TOKEN`), `STT_BASE_URL` (по умолчанию `https://api.groq.com/openai/v1`).
  LMStudio и прочие локальные серверы подключаются той же тройкой
  (`STT_BASE_URL=http://localhost:1234/v1`); OpenRouter endpoint'а
  `/audio/transcriptions` не имеет;
- промежуточные файлы лежат во временной папке (см. «Рабочие файлы»): `movie.audio0.srt` —
  распознанные субтитры (дальше весь пайплайн работает с ними: выход `movie.audio0.ru.srt`
  рядом с видео), `movie.audio0.stt/` — чанки FLAC, их JSON-кэш и план разрезки. Повторный
  запуск переиспользует кэш — готовые чанки заново не транскрибируются и ffprobe/ffmpeg почти
  не зовутся; нужно перераспознать (другой моделью) — удалите там `movie.audio0.srt` и `movie.audio0.stt/`;
- аудио режется на чанки ≤10 минут по тишине (слова на стыках не рвутся; если в окне
  тишины нет — жёсткий разрез), чанки транскрибируются последовательно, 429/5xx/сеть
  ретраятся как в переводе. Groq: `whisper-large-v3-turbo` ≈ $0.04/час аудио,
  `whisper-large-v3` ≈ $0.11/час;
- `--stt-lang en` — подсказка языка речи, ISO-639-1 (улучшает точность и латентность);
  `--stt-limit N` — транскрибировать только первые N чанков (пробный прогон, SRT будет
  частичным);
- реплики приводятся к субтитровым нормам всегда, без флага: сегменты длиннее ~7.5 с
  или ~84 символов режутся — в первую очередь по границам предложений, затем по паузам
  в речи (word-таймстампы), в крайнем случае по центру; «редкие» сегменты поверх музыки
  (пара слов на 30-секундное окно декодирования) обрезаются по реальному таймспану слов,
  а если таймстампы слов сами вырождены (слово «длится» десятки секунд — так Whisper
  галлюцинирует поверх музыки) — реплика ужимается до ~3 с, чтобы не висеть на экране.
  A/B на «Sync»: `whisper-large-v3-turbo` и `whisper-large-v3` после такой обработки
  эквивалентны, поэтому по умолчанию дешевле турбо (≈$0.04/час против ≈$0.11/час).

### Чистка входа

Перед переводом вход чистится (в памяти, входной файл не меняется):

- **SDH-текст** — реплики, состоящие целиком из «(...)» или «[...]» («(CAT MIAOWS)»,
  «[GOBLIN GRUNTING]»), удаляются; в смешанных репликах скобочная часть вырезается
  («WOMAN: (ON PHONE) It's Packenham.» → «WOMAN: It's Packenham.»).
- **Дубликаты** — идущие подряд реплики с байт-в-байт одинаковым текстом сливаются в одну
  с суммарным таймингом (некоторые субтитры перезаписывают одну реплику каждые ~40 мс);
  пауза между склеиваемыми репликами не больше 1 с, одиночные повторы «No. … No.» не трогаются.

Номера реплик сохраняются, поэтому `--range A-B` работает по нумерации исходного файла,
а вывод всегда собирается из почищенного списка. Чистка идемпотентна.

### Основные флаги

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `-i, --interactive` | без аргументов — да | вопросы с выбором стрелками, см. «Интерактивный режим» |
| `-o, --out <path>` | `<input>.ru.srt` | выходной файл; вход никогда не перезаписывается |
| `--about <text>` / `--about-file <path>` | `<input>.txt`, затем `<input>.md`, если есть | синопсис + глоссарий, см. ниже |
| `--sub-track <n>` | — | дорожка встроенных субтитров видео; для видео без флага — печатается список |
| `--audio-track <n>` | — | транскрибировать аудиодорожку видео (Whisper) и переводить её |
| `--stt-model <id>` / `--stt-base-url <url>` / `--stt-api-key <key>` | env `STT_MODEL` / `STT_BASE_URL` / `STT_API_KEY` | параметры STT-endpoint'а; модель обязательна |
| `--stt-lang <iso>` | — | язык речи для Whisper (ISO-639-1) |
| `--stt-limit <n>` | — | только первые n чанков STT (пробный прогон) |
| `--from` / `--to` | авто / `Russian` | языки |
| `--context-before <n>` / `--context-after <n>` | 3 / 3 | окно контекста (перевод до, оригинал после) |
| `--concurrency <n>` | 1 | параллельные вызовы, см. «Скорость» |
| `--max-line-len <n>` | 42 | переносы строк перевода |
| `--range A-B`, `--limit N` | всё | прогон куска; с `--resume` лимит считает непереведённые |
| `--delay <ms>` | 0 | пауза между вызовами |
| `--price-in/--price-out` | — | USD за 1M токенов, для строки стоимости |
| `--resume`, `--dry-run`, `-q` | — | см. выше |

При невосполнимой ошибке (нет денег на счету, битый ключ — HTTP 400/401/403/404) прогон сразу
останавливается, прогресс сохранён в sidecar, дальше — `--resume`. Сетевые сбои, 429 и 5xx
ретраятся: 5 попыток с паузами 1/2/4/8/16 c и уважением `Retry-After`. Каждая ретрая пишется
в stderr (`повтор 2/5 через 4 с (HTTP 429)`): если таких строк много — вас троттлят, поможет
`--concurrency 1` + `--delay`.

## Скорость

Последовательный прогон — это примерно `реплики × латентность одного вызова` (промпт ~1k токенов +
генерация), то есть час-полтора на фильм. Ускориться можно так:

```sh
subs-translate movie.srt --concurrency 4
```

До N вызовов летят одновременно. Контекст при этом деградирует мягко: реплика получает русский
контекст тех предыдущих, что уже успели доделаться (при N ≤ `--context-before` + 1, т.е. ≤4 по
умолчанию, контекст почти всегда полный); «следующие реплики» в оригинале не страдают никогда.
Sidecar, `--resume` и порядок сборки от N не зависят.

Прогресс-строка показывает суммарные токены за прогон; повызывные цифры лежат в sidecar
(`tokens`). Учтите: `out` включает и reasoning-токены GLM, поэтому он непропорционально велик.

## Несколько endpoint'ов (round-robin)

Одного провайдера не хватает по лимитам — запросы можно разложить по кругу на несколько:

```sh
subs-translate movie.srt --endpoints endpoints.json --concurrency 3
cp endpoints.example.json endpoints.json   # и вписать OPENROUTER_API_KEY= в .env
```

Формат — JSON-массив; порядок записей = порядок round-robin (задублированная запись получает
пропорционально больше вызовов — это и есть способ выставлять веса):

```json
[
  { "name": "pareto",  "baseUrl": "https://api.paretoinference.com/v1", "apiKey": "env:OPENAI_API_KEY",     "model": "z-ai/glm-5.3-flash" },
  { "name": "or-glm",  "baseUrl": "https://openrouter.ai/api/v1",       "apiKey": "env:OPENROUTER_API_KEY", "model": "z-ai/glm-5.3-flash", "extraBody": { "usage": { "include": true } } },
  { "name": "or-muse", "baseUrl": "https://openrouter.ai/api/v1",       "apiKey": "env:OPENROUTER_API_KEY", "model": "meta/muse-spark-1.3-contributor", "extraBody": { "usage": { "include": true } } }
]
```

- `apiKey` — либо `"env:ИМЯ_ПЕРЕМЕННОЙ"` (рекомендуется), либо literal-ключ;
- `extraBody` прокидывается в тело запроса как есть; OpenRouter считает токены только с
  `usage: {include: true}`, иначе в счётчике будут нули;
- каждый вызов (включая первый) идёт к следующему живому endpoint'у; ретрай после 429/5xx тоже
  уезжает к следующему, с обычным backoff'ом;
- сломанный endpoint (HTTP 400/401/403/404 или 5 неудач подряд) отключается с предупреждением
  `⚠ endpoint ... отключён`, прогон продолжается на остальных; когда мертвы все — остановка
  с `--resume`-подсказкой;
- в итоговой строке — разбивка по endpoint'ам (реплики/токены), в sidecar у каждой реплики
  записана фактическая модель.

Строгий round-robin означает, что разные модели переводят соседние реплики — стиль может
плавать; синопсис с глоссарием имён в about-файле это частично гасит.

## About-файл: синопсис и глоссарий

`--about` / `--about-file` не обязателен, но именно он делает перевод «человеческим».
Без флагов подхватывается файл рядом со входом с тем же именем: для `movie.mkv` или `movie.srt`
сначала `movie.txt`, затем `movie.md`. Шаблон `movie.txt`:

```markdown
«Деление» (The Division), криминальный триллер, 2024.

Синопсис: детектив Марр расследует исчезновение своего напарника Голлиса и выходит
на коррупционную схему в собственном отделе.

Регистр и тон: сухой, усталый нуар. Мужики между собой на «ты», к начальству — на «вы».
Сарказм не сглаживать.

Names and terms:
- Hollis — Голлис (не «Холлис»)
- Detective Marr — детектив Марр, он же «марр» в ругательствах
- The Division — Отдел (в диалогах без артикля)
- lockup — обезьянник
```

Глоссарий живёт прямо внутри about-файла — отдельного флага нет.

## Рабочие файлы

Всё промежуточное — sidecar, извлечённые и распознанные `.srt`, STT-кэш `.stt/` — лежит не
рядом с видео, а во временной папке ОС: `<tmp>/subs-translate/<папка>-<хеш>/` (на Linux
обычно `/tmp/subs-translate/…`; одна папка на каждую исходную директорию, путь печатается при
запуске). Рядом с входом появляется только готовый перевод. После успешного прогона файлы
не удаляются — их переиспользуют `--resume` и STT-кэш; удалить можно вручную. Учтите, что
`/tmp` может очищаться при перезагрузке — тогда прогресс и кэш распознавания пропадут.

## Resume и sidecar

Каждая переведённая реплика дописывается в `<tmp>/subs-translate/…/<out>.progress.jsonl`:

```json
{"i":413,"h":"9f86d0818...","src":"He didn't <i>leave</i>.","ru":"Он не <i>уходил</i>.","tokens":{"in":812,"out":31},"model":"z-ai/glm-5.3-flash","at":"2026-09-12T17:04:11.902Z"}
```

- файл append-only, при повторных прогонах новые записи перекрывают старые;
- `--resume` переиспользует запись только если хеш **исходного текста** реплики совпал;
- хеш считается по тексту реплики, а не по синопсису: **правка about-файла не инвалидирует
  sidecar**. Хотите переперевести кусок с новым синопсисом — `--range 100-130` (можно с `--resume`,
  новые записи перекроют старые);
- русский контекст для следующих реплик читается из этого же файла, так что после `--resume`
  история не теряется;
- с `--resume` флаг `--limit` считает **непереведённые** реплики: `--resume --limit 20` означает
  «следующие 20 новых», а не «первые 20 файла». Если в диапазоне всё уже переведено, утилита
  скажет об этом и не будет делать ни одного вызова.

Итоговый `.srt` собирается из sidecar-записей; реплики вне выбранного диапазона остаются
в оригинале. Индексы и позиции `{\anN}` не трогаются никогда; тайминги меняются только
при склейке дубликатов на этапе чистки. Переносы строк перевода пересчитываются при каждой
сборке, так что `--resume` переформатирует уже переведённые реплики без повторных вызовов.

## Что preserved, что переводится

- `<i>`/`<b>` и прочая inline-разметка сохраняются вокруг переведённых слов;
- `{\an8}`-позиции вырезаются из текста перед моделью и приклеиваются обратно;
- SDH-скобки «(...)»/«[...]» вырезаются до модели, см. «Чистка входа»;
- тире-диалог (`- Привет…`) сохраняется: такие реплики не склеиваются и не перебалансируются;
- переносы строк: реплика влезает в одну строку — будет одна; иначе строки балансируются по
  видимой длине (теги не считаются), а тег, разрезанный переносом, закрывается в конце строки
  и открывается в начале следующей;
- вход: UTF-8 или cp1251 (BOM допустим), выход: UTF-8 без BOM, CRLF, ≤2 строки по ~42 символа.

## Разработка

Код написан на TypeScript и исполняется Node.js ≥ 24 напрямую (native type stripping) —
сборка не нужна ни для разработки, ни для запуска.

```sh
npm run typecheck   # tsc --noEmit
npm test            # node --test, подхватывает test/*.test.ts
npm run check       # и то и другое
```

Тесты — `node:test`, без внешних зависимостей: round-trip SRT, cp1251, чистка входа,
переносы, resume/assembly, санитайзер и логика ретраев (со стабом вместо API), разбор
ffprobe-вывода и извлечение встроенных субтитров через ffmpeg, планировщик чанков STT
(тишина → границы), разбор verbose_json и склейка сегментов. Тесты, требующие
ffmpeg/ffprobe, сами пропускаются, если их нет; интеграционный тест STT-эндпоинта
выполняется только при настроенных `STT_API_KEY`/`GROQ_API_TOKEN` + `STT_MODEL`
и стоит доли цента.

Сборка в самодостаточный бинарник (без Node.js на целевой машине) — через Bun
(`bun build --compile` embed'ит рантайм в ELF/PE-бинарник). Нужен только Bun
на машине сборки; для целевой машины ничего не нужно, кроме amd64 и glibc
(или musl для Alpine):

```sh
npm run build:binary              # linux-x64  → dist/subs-translate-linux-x64
npm run build:binary:linux-musl   # alpine     → dist/subs-translate-linux-x64-musl
npm run build:binary:windows      # windows    → dist/subs-translate-windows-x64.exe
npm run build:binary:mac          # macOS x64  → dist/subs-translate-darwin-x64
npm run build:binary:all          # все четыре
```

Кросс-компиляция работает из любой ОС: таргет задаётся флагом `--target`.
Бинарники получаются ~100 МБ (внутри рантайм). Проверка:

```sh
./dist/subs-translate-linux-x64 subs.srt --dry-run
```
