# subs-translator

Переводит `.srt`-субтитры **реплика за репликой** против OpenAI-совместимого API, но не «в вакууме»:
модель видит синопсис фильма (тон, регистр, глоссарий имён), уже сделанный перевод предыдущих реплик
и оригинал следующих. Поэтому `ты`/`вы` выбираются осмысленно, имена не «плывут» от сцены к сцене,
а ответ читается как ответ.

Один вызов API на реплику (~900–1400 на полнометражный фильм). Строго последовательно, без concurrency.

## Установка

Нужен Node.js ≥ 24.

```sh
npm install
cp .env.example .env      # и вписать ключ
```

`.env`:

```
PARETO_API_KEY=sk-...
SUBS_BASE_URL=https://api.paretoinference.com/v1
SUBS_MODEL=z-ai/glm-5.3-flash
```

Любое значение можно переопределить флагами `--api-key` / `--base-url` / `--model`;
вместо `PARETO_API_KEY` подойдёт `OPENAI_API_KEY`, вместо `SUBS_BASE_URL` — `OPENAI_BASE_URL`.

## Использование

```sh
subs-translate movie.srt                      # → movie.ru.srt (+ movie.ru.srt.progress.jsonl)
subs-translate movie.srt --limit 5            # пробный прогон: первые 5 реплик
subs-translate movie.srt --range 100-130      # только реплики 100–130
subs-translate movie.srt --resume             # докончить после обрыва
subs-translate movie.srt --dry-run            # показать полный промпт первой реплики и выйти
subs-translate movie.srt --about-file movie.about.md
subs-translate movie.srt -o out/ru.srt
subs-translate movie.srt --price-in 0.3 --price-out 1.2   # + оценка стоимости
```

Прогресс (реплика k/n, время, ETA, токены) идёт в stderr; stdout остаётся чистым. `-q` выключает прогресс.

### Основные флаги

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `-o, --out <path>` | `<input>.ru.srt` | выходной файл; вход никогда не перезаписывается |
| `--about <text>` / `--about-file <path>` | `<input>.about.md`, если есть | синопсис + глоссарий, см. ниже |
| `--from` / `--to` | авто / `Russian` | языки |
| `--context-before <n>` / `--context-after <n>` | 3 / 3 | окно контекста (перевод до, оригинал после) |
| `--concurrency <n>` | 1 | параллельные вызовы, см. «Скорость» |
| `--max-line-len <n>` | 42 | переносы строк перевода |
| `--range A-B`, `--limit N` | всё | прогон куска; с `--resume` лимит считает непереведённые |
| `--delay <ms>` | 0 | пауза между вызовами |
| `--price-in/--price-out` | — | USD за 1M токенов, для строки стоимости |
| `--resume`, `--dry-run`, `-q` | — | см. выше |

При невосполнимой ошибке (нет денег на счету, битый ключ — HTTP 400/401/403/404) прогон сразу
останавливается, прогресс сохранён в sidecar, дальше — `--resume`. Сетевые сбои, 429 и 5xx
ретраятся: 5 попыток с паузами 1/2/4/8/16 c и уважением `Retry-After`. Каждая ретрая пишется
в stderr (`повтор 2/5 через 4 с (HTTP 429)`): если таких строк много — вас троттлят, поможет
`--concurrency 1` + `--delay`.

## Скорость

Последовательный прогон — это примерно `реплики × латентность одного вызова` (промпт ~1k токенов +
генерация), то есть час-полтора на фильм. Ускориться можно так:

```sh
subs-translate movie.srt --concurrency 4
```

До N вызовов летят одновременно. Контекст при этом деградирует мягко: реплика получает русский
контекст тех предыдущих, что уже успели доделаться (при N ≤ `--context-before` + 1, т.е. ≤4 по
умолчанию, контекст почти всегда полный); «следующие реплики» в оригинале не страдают никогда.
Sidecar, `--resume` и порядок сборки от N не зависят.

Прогресс-строка показывает суммарные токены за прогон; повызывные цифры лежат в sidecar
(`tokens`). Учтите: `out` включает и reasoning-токены GLM, поэтому он непропорционально велик.

## Несколько endpoint'ов (round-robin)

Одного провайдера не хватает по лимитам — запросы можно разложить по кругу на несколько:

```sh
subs-translate movie.srt --endpoints endpoints.json --concurrency 3
cp endpoints.example.json endpoints.json   # и вписать OPENROUTER_API_KEY= в .env
```

Формат — JSON-массив; порядок записей = порядок round-robin (задублированная запись получает
пропорционально больше вызовов — это и есть способ выставлять веса):

```json
[
  { "name": "pareto",  "baseUrl": "https://api.paretoinference.com/v1", "apiKey": "env:PARETO_API_KEY",     "model": "z-ai/glm-5.3-flash" },
  { "name": "or-glm",  "baseUrl": "https://openrouter.ai/api/v1",       "apiKey": "env:OPENROUTER_API_KEY", "model": "z-ai/glm-5.3-flash", "extraBody": { "usage": { "include": true } } },
  { "name": "or-muse", "baseUrl": "https://openrouter.ai/api/v1",       "apiKey": "env:OPENROUTER_API_KEY", "model": "meta/muse-spark-1.3-contributor", "extraBody": { "usage": { "include": true } } }
]
```

- `apiKey` — либо `"env:ИМЯ_ПЕРЕМЕННОЙ"` (рекомендуется), либо literal-ключ;
- `extraBody` прокидывается в тело запроса как есть; OpenRouter считает токены только с
  `usage: {include: true}`, иначе в счётчике будут нули;
- каждый вызов (включая первый) идёт к следующему живому endpoint'у; ретрай после 429/5xx тоже
  уезжает к следующему, с обычным backoff'ом;
- сломанный endpoint (HTTP 400/401/403/404 или 5 неудач подряд) отключается с предупреждением
  `⚠ endpoint ... отключён`, прогон продолжается на остальных; когда мертвы все — остановка
  с `--resume`-подсказкой;
- в итоговой строке — разбивка по endpoint'ам (реплики/токены), в sidecar у каждой реплики
  записана фактическая модель.

Строгий round-robin означает, что разные модели переводят соседние реплики — стиль может
плавать; синопсис с глоссарием имён в about-файле это частично гасит.

## About-файл: синопсис и глоссарий

`--about` / `--about-file` не обязателен, но именно он делает перевод «человеческим».
Шаблон `movie.about.md`:

```markdown
«Деление» (The Division), криминальный триллер, 2024.

Синопсис: детектив Марр расследует исчезновение своего напарника Голлиса и выходит
на коррупционную схему в собственном отделе.

Регистр и тон: сухой, усталый нуар. Мужики между собой на «ты», к начальству — на «вы».
Сарказм не сглаживать.

Names and terms:
- Hollis — Голлис (не «Холлис»)
- Detective Marr — детектив Марр, он же «марр» в ругательствах
- The Division — Отдел (в диалогах без артикля)
- lockup — обезьянник
```

Глоссарий живёт прямо внутри about-файла — отдельного флага нет.

## Resume и sidecar

Каждая переведённая реплика дописывается в `<out>.progress.jsonl`:

```json
{"i":413,"h":"9f86d0818...","src":"He didn't <i>leave</i>.","ru":"Он не <i>уходил</i>.","tokens":{"in":812,"out":31},"model":"z-ai/glm-5.3-flash","at":"2026-09-12T17:04:11.902Z"}
```

- файл append-only, при повторных прогонах новые записи перекрывают старые;
- `--resume` переиспользует запись только если хеш **исходного текста** реплики совпал;
- хеш считается по тексту реплики, а не по синопсису: **правка about-файла не инвалидирует
  sidecar**. Хотите переперевести кусок с новым синопсисом — `--range 100-130` (можно с `--resume`,
  новые записи перекроют старые);
- русский контекст для следующих реплик читается из этого же файла, так что после `--resume`
  история не теряется;
- с `--resume` флаг `--limit` считает **непереведённые** реплики: `--resume --limit 20` означает
  «следующие 20 новых», а не «первые 20 файла». Если в диапазоне всё уже переведено, утилита
  скажет об этом и не будет делать ни одного вызова.

Итоговый `.srt` собирается из sidecar-записей; реплики вне выбранного диапазона остаются
в оригинале. Тайминги, индексы и позиции `{\anN}` не трогаются никогда.

## Что preserved, что переводится

- `<i>`/`<b>` и прочая inline-разметка сохраняются вокруг переведённых слов;
- `{\an8}`-позиции вырезаются из текста перед моделью и приклеиваются обратно;
- `[ЗВУК ДВЕРИ]` и строчки песен **переводятся**, скобки и регистр сохраняются;
- тире-диалог (`- Привет…`) сохраняется;
- вход: UTF-8 или cp1251 (BOM допустим), выход: UTF-8 без BOM, CRLF, ≤2 строки по ~42 символа.

## Разработка

Код написан на TypeScript и исполняется Node.js ≥ 24 напрямую (native type stripping) —
сборка не нужна ни для разработки, ни для запуска.

```sh
npm run typecheck   # tsc --noEmit
npm test            # node --test, подхватывает test/*.test.ts
npm run check       # и то и другое
```

Тесты — `node:test`, без внешних зависимостей: round-trip SRT, cp1251, переносы, resume/assembly,
санитайзер и логика ретраев (со стабом вместо API).

Сборка в самодостаточный бинарник (например, для NAS без Node): бандлить esbuild'ом
(`esbuild bin/subs-translate.ts --bundle --platform=node`) и дальше — Node SEA или
`bun build --compile` на получившемся файле.
